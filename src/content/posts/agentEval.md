# Agent记忆压缩机制
## 1. 滑动窗口
只保留最近N轮对话，超出窗口的历史直接丢弃。

## 2. 摘要压缩
把多轮对话浓缩成简短摘要，替代原始长对话文本。

## 3. 重要性过滤
### 规则过滤（基于关键词打分，简单但容易误判）
打分规则：
1. 如果这段文字里面包含关键词：需求、决定、确认、方案 → +10分
2. 如果后面的对话里多次引用过这段话 → +5分
3. 如果是闲聊（哈哈、好的、收到、嗯嗯） → -8分
4. 总分小于0分 → 删掉这条记录

> 模拟一段对话，跑一遍规则
> - 对话 1：“我们决定接口使用 POST 方法” → 有【决定】，+10 分 → 高分，保留
> - 对话 2：“哈哈，好嘞” → 闲聊，-8 分 → 低分，删掉
> - 对话 3：“需求：接口要支持分页” → 有【需求】，+10 分 → 保留
> - 对话 4：“收到” → 闲聊，-8 分 → 删除

但是这是死的，容易出现误判

### LLM过滤
让大模型一条一条读历史消息，理解语义，判断这条记录重不重要。
- 优点：准确率更高，能看懂一句话真正含义，不会像关键词那样死板。
- 缺点：每一条记录都要调用一次大模型，花钱、消耗 token，开销大。

所以一般攒一大堆历史，批量一次性清理，不会每来一条消息就实时调用 LLM 打分。

## 4. 观察遮蔽
原理：全部历史永久保存在数据库，不删除。 每次组装 prompt 发给 LLM 前，挑选和当前任务阶段相关的历史，无关内容本轮不放进 prompt（临时隐藏）。

两种判断相关 / 无关的实现方式：
1）规则打标签：代码直接读取预定义标签，无额外 LLM 调用，每轮仅 1 次主请求；缺点：死板容易错
2）LLM 语义分类：
任务阶段切换时，额外 1 次 LLM 调用，给历史打上【相关 / 无关】标签
标签会缓存，同一任务阶段后续多轮对话复用标签，不再重复调用
拿到标签后，只把相关历史填入 prompt，发起主任务 LLM 请求

- 优点：信息不会丢失；按需选择送入模型的内容，减少 token 消耗
- 缺点：如果用 LLM 做相关性判断，阶段切换会带来额外 LLM 开销

## 5. 主动压缩
### 结构化抽取
不保存完整对话原文，只提取对话里的事实、状态，存成结构化字段。

# 计算层优化：Prompt Caching（KV 前缀缓存）
前提：信息层已经确定好要送入 prompt 的全部内容。不修改 prompt 内容，只优化推理算力开销。

## 原理
LLM 推理分为两步：
① Prefill：对所有输入 token 计算注意力 KV 张量，长文本下这一步最耗算力、成本最高
② Decode：逐 token 生成回答

Prompt Caching：缓存固定前缀的 KV 中间计算结果，不是缓存最终输出答案。
- Claude：需要后端在 API 参数添加cache_control标记片段，手动开启缓存（官方 API 定义）
- DeepSeek：自动前缀缓存，无需额外参数；服务商后台自动比对 prompt 开头文本，完全一致自动命中缓存

命中缓存效果：跳过固定前缀重复的 prefill 计算，只对新增内容做 prefill；模型依然会重新生成回答，答案不固定。
收益：降低输入 token 费用、减少首字响应延迟；非常适合 Agent（固定 system 提示词、长期记忆）

## 重要区分
Prompt Caching（服务商 KV 缓存）：复用中间计算，模型仍然运行生成新答案 不要删除护着改变任何内容 只需要改成Md格式即可
